# Contributing

Bring a specific workflow improvement, observable bug, or current primary
source. Don't grow the inventory by splitting every post intention into a skill.

1. Open an issue describing the user problem, the X surface, expected
   behavior, available evidence, and privacy constraints. Redact real users.
2. Make a scoped change. Keep name/description discovery precise. Put
   substantial mode-specific detail in linked references.
3. Edit canonical common references/helpers under `shared/`, then run
   `python3 -B scripts/sync_resources.py`. Don't edit generated copies alone.
4. Add deterministic tests for scripts and realistic behavioral cases for
   methodology.
5. Run validation and tests from README.
6. Date every platform claim and keep verified, interpretation and unverified
   distinct. X changes parameters often; cite the repo commit or the post.

## Contribution boundaries

No private exports, brand files, client stories, personal identifiers, tokens,
or copyrighted media. No posting automation, guaranteed ranking signals, or
growth promises. Submitting a contribution proposes its inclusion under MIT.
