# Architecture and authority

User facts, voice, objectives and permissions
-> a selected X workflow
-> specialist instructions and available helpers
-> an X-native draft or evidence-backed recommendation.

No master skill is required. Chain specialists only when the deliverable needs it.

| Capability | Authority | Related handoff |
| --- | --- | --- |
| Single posts, quote posts, hooks | x-post | Voice revision in x-human |
| Long posts, threads, Articles | x-longform | Short version to x-post |
| Replies on other people's posts, networking | x-engage | Own-post replies to x-reply |
| Replies under own posts | x-reply | Common questions to x-post |
| Profile and pinned post | x-presence | Plan/audit when requested |
| Spaces and group chats | x-spaces | Recap to x-post, results to x-audit |
| Daily rhythm and rotation | x-plan | Drafts to x-post/x-longform |
| Published-account learning | x-audit | Evidence to x-plan |
| Source extraction | x-repurpose | Briefs to format skills |
| Voice revision | x-human | Return the revised artifact |

Canonical common resources live in `shared/`; `scripts/sync_resources.py`
bundles identical copies plus the license inside every skill, and the
comparison helper into x-audit. Every folder can be copied independently.
User-specific context is runtime input, not a modification of the methodology.
