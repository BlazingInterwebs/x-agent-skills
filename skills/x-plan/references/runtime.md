# Runtime and task boundaries

This collection is draft-only. It has no API, connector, browser automation,
account authorization, publishing integration, or scheduler. The user posts
by hand. Use only capabilities the current host actually exposes. Never
pretend a tool or sibling skill ran.

## Never do

Post, schedule, like, repost, follow, DM, change profile or settings, buy or
change a subscription, or join/leave anything on the user's behalf.

## Intake

Use supplied information first: account, audience, objective, deliverable,
the facts behind any claim, and the user's context (voice, story, pillars,
offer, CTA, mix, funnel weights, posts per day, link placement, CTA limits). Ask only for missing information that materially changes
the task. A reasonable assumption may support a provisional draft; label it.
Read private context only when the user has authorized it for this task.

## Placeholders

Leave these visible until the user fills them: `{{OFFER}}`, `{{PILLARS}}`,
`{{CTA}}`, `{{RESULT}}`. Never publish a placeholder as a fact.

## Voice

Match the user's supplied voice. Without it, default to: conversational,
contractions, brief, no corporate jargon, no hype, no guru tone, no generic
AI phrasing. Check the user's punctuation rules (some voices ban em dashes).

Every draft is a starting point, never final copy. Replies especially: an
agent-drafted reply must be rewritten by the user in their own words before
it is posted. Say so when delivering reply drafts.

## Draft output

```
Mix: <from context>
Stage: reach | trust | sales
Hook type: bold claim | callout | curiosity gap | clear outcome | contrarian
Format: single | long post | thread | Article | quote | reply | video clip
CTA: none | soft: <the one line>
Draft:
<text>
First reply: <link line, only when context puts links in the first reply>
Alt hook: <text>
Needs from the user: <any {{RESULT}} or fact to confirm, or "none">
```

Return publishable copy separated from notes. State assumptions and
unverified claims outside the copy.

## Freshness

Check the "Reviewed" date in [evidence](evidence.md). If it's more than 60
days old, re-check the algorithm repo and X's posts before quoting a claim.
